# User Story 1.4: Attach the last battery reading to the walk-start request

## Story

**As a** developer reading a walk that crashed or refused
**I want** the battery voltage the duck had when Walk was pressed
**So that** a brown-out is visible in the same PostHog row as the failure, without asking anyone

## Background

`/api/voltage` (`scripts/tnkr_server.py:3403`) returns `volts` and a `health` band to
Studio, which shows the battery chip and warns on it. None of that reaches telemetry: the
handler never calls `add_telemetry_props`, so the fleet has no voltage data at all. During
the 2026-09 incident a brown-out could not be ruled in or out.

Voltage does **not** gate the walk (product decision 2026-09-09: Studio already warns, a
duck at 7.2 V can still walk). It rides along as information.

A fresh read at walk start is not cheap: rustypot 0.1.0 exposes no voltage read (verified:
`FeetechController` has `get_present_position` and gain/torque writes only), and the pypot
path in `/api/voltage` closes rustypot, opens a second stack on the adapter, and cost up to
2.5 s on a flaky bus in the incident data. So this story **caches** the last `/api/voltage`
result on the server and attaches it, with its age, to the walk-start request's telemetry.
Studio polls `/api/voltage` about every 30 s while connected, so the reading is rarely old.

Builds on 1.1 (the `PreflightReport` and the telemetry call site).

## Acceptance Criteria

### Core Functionality

- [ ] **Cache on read**: `/api/voltage` stores `{"volts", "health", "max_temp_c",
      "temp_health", "at": time.monotonic()}` in a module-level `_last_voltage` on every
      successful read. A failed read leaves the cache untouched.
- [ ] **Voltage reaches telemetry**: `/api/voltage` itself calls
      `add_telemetry_props(volts=..., health=..., max_temp_c=..., temp_health=...)` so
      its `api_request_completed` row carries the reading.
- [ ] **Attached at walk start**: `_walk_start_locked` adds `volts_last`,
      `volts_health_last`, `volts_age_s` (rounded to 1 dp) when the cache is populated, on
      both the pass and refusal paths. Absent cache: the props are omitted, never null.
- [ ] **Never a gate**: no voltage value refuses a walk.

### User Experience

- [ ] **Zero added latency**: no bus traffic at walk start for voltage.
- [ ] **No new operator copy**: nothing changes on screen.

### Technical Requirements

- [ ] **Age is honest**: `volts_age_s` measures from the read that populated the cache,
      not from the last request.
- [ ] **Reset on server start**: the cache is process memory; a restarted agent has no
      reading until Studio polls.

## Expected User Flow

```bash
# Studio has been connected for a while; it polled /api/voltage 12 s ago
$ curl -s -X POST localhost:8000/api/walk/start -d '{}'
{"success":true,"pid":4242}
# api_request_completed for /api/walk/start:
#   preflight_ms=71 servos_responding=14 imu_present=true
#   volts_last=7.62 volts_health_last=ok volts_age_s=12.3

# PostHog, the next incident:
SELECT properties.volts_last, properties.error_code FROM events
WHERE event = 'api_request_failed' AND properties.endpoint = '/api/walk/start'
```

### Technical Considerations

#### Why not read at walk start

- **rustypot has no voltage call** in the pinned 0.1.0. Adding one means a Rust change
  and a rebuild on every Pi.
- **pypot means a bus handoff**: `/api/voltage` releases rustypot under `BUS_LOCK` and
  opens pypot. Doing that inside the pre-flight would add seconds and a second stack open
  right before the walk's own open.
- **Studio already polls**: the cache is fresh in practice. `volts_age_s` says when it is
  not.

#### Error Scenarios to Handle

- No reading yet (agent just started, Studio not connected): props omitted.
- Reading older than a few minutes (Studio tab left open, duck power-cycled): still
  attached, age makes it interpretable. No staleness cut-off; the analyst decides.
- `/api/voltage` 503: cache untouched; the failure event already carries the message.

#### Performance & UX

- Two dictionary reads at walk start. Nothing measurable.
