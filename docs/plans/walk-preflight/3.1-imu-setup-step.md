# User Story 3.1: Add the IMU check to the duck's setup steps

## Story

**As a** duck operator connecting in Studio
**I want** the setup to check the IMU answers, right after it checks the motors
**So that** an unplugged IMU is caught at connect and not after seven walks

## Background

Repo: **tnkr-studio**. Requires runtime story 1.3 (`POST /api/imu/check`) on the duck;
against an older agent the check fails with `AGENT_OUTDATED` and its upgrade sentence,
which is correct.

The duck manifest has one `CheckStep` today (`server/trlc_studio/robots/openduck_mini/manifest.py:75-83`):

```python
CheckStep(id="wake-motors", title="Wake the motors",
          purpose="Every joint should answer a position read.", verify="motors", timeout_ms=15000)
```

`VerifyKind = Literal["ports", "motors", "cameras"]` (`server/trlc_studio/models.py:20`)
is the closed set of things a driver can verify; `driver.check` (`driver.py:533`) raises
`UNKNOWN_CHECK` for anything else. Adding `"imu"` touches the literal, the driver, the fake
driver, the sim agent, the frontend type, the OpenAPI dump, and the frontend manifest
fixture whose parity with the backend is enforced by `server/tests/test_bimanual.py`.

`session.run_check` (`services/session.py:793`) already runs any `CheckStep` under a
timeout and records `props["check"] = step.verify` on `studio_check_completed`, so the
new step shows up in PostHog as `check=imu` with no telemetry work.

### Key Dependencies

- **Runtime 1.3** deployed on the duck for the check to pass; without it the step fails
  with `AGENT_OUTDATED`, by design.

### Core Functions to Implement

```python
# server/trlc_studio/models.py
VerifyKind = Literal["ports", "motors", "cameras", "imu"]

# agent_types.py
class ImuCheckResult(_AgentModel):
    present: bool

# agent_client.py
def check_imu(self) -> ImuCheckResult:
    return ImuCheckResult.model_validate(self._request("POST", "/api/imu/check"))

# driver.py
def check(self, verify: VerifyKind, timeout_s: float, abort: threading.Event) -> None:
    if verify == "motors": ...            # unchanged
    elif verify == "imu":
        self.agent.check_imu()            # raises StudioError on 502/404/transport
    else:
        raise StudioError(ErrorCode.UNKNOWN_CHECK, f"duck has no {verify!r} check")
```

### Technical Considerations

#### Manifest is data, but its strings are copy

- `title` and `purpose` are shown to the operator. "Wake the IMU" matches "Wake the
  motors"; "The tilt sensor should answer." says the specific thing. No em dashes.

#### Error Scenarios to Handle

- Agent lacks the route (older runtime): 404 → `AGENT_OUTDATED` → existing upgrade
  sentence. The step fails rather than silently passing.
- Walk running when the check is triggered: 409 → `INVALID_STATE`; `run_check` already
  refuses while the bus is busy.
- Transport failure mid-check: the four transport codes, unchanged.

#### Performance & UX

- Under 10 ms with an existing IMU handle on the Pi; the 10 s timeout is generous for a
  cold handle (~0.75 s).
