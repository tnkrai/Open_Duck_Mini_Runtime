# User Story 3.2: Show duck copy when a duck check fails

## Story

**As a** duck operator whose connect check failed
**I want** the failure sentence written for a duck, naming the part
**So that** I am not told to check "the arm" when my duck's IMU cable is loose

## Background

Repo: **tnkr-studio** (`app/src`). Builds on 2.1 (`lastErrorJoint`, duck sentences) and
3.1 (the `wake-imu` step).

`app/src/components/VerifyStep.tsx:141-150` runs the manifest's checks and, on failure,
resolves the reason as `strings.errors[code]` only. Connect failures on the same screen go
through `connectOutcome(connection, lastErrorCode, network ? 'duck' : 'arm')`
(`app/src/lib/connectOutcome.ts:32`), which does pick the duck vantage. So today a duck
check that fails renders the arm sentence, and the new IMU check would fail with
"A joint didn't answer. Check the arm has power" on the one screen built to show it.

This story makes the check-failure path consult `strings.connect.duckErrors` and
`strings.duckErrors` for a network robot, through `plainCopy` with the joint label, the
way the Drive toast does after 2.2.

## Acceptance Criteria

### Core Functionality

- [ ] **Resolver**: a shared `checkFailureText(code, joint, variant, robot)` returns, for
      `variant === 'duck'`, `plainCopy(connect.duckErrors[code] ?? duckErrors[code] ??
      errors[code] ?? fallback, { jointLabel })`; for `'arm'`, `errors[code] ?? fallback`
      as today.
- [ ] **VerifyStep uses it**: the failure branch at `VerifyStep.tsx:141-150` calls the
      resolver with `lastErrorCode`, `lastErrorJoint`, and the same `network ? 'duck' :
      'arm'` selector `connectOutcome` uses.
- [ ] **Joint label**: `lastErrorJoint` is mapped to the manifest label, falling back to
      the raw name.
- [ ] **Template preserved**: `t.checkFailed.replace('{reason}', reason)` /
      `t.checkFailedPlain` behaviour unchanged; only `reason` changes.

### User Experience

- [ ] **IMU**: a failed `wake-imu` shows "The IMU sensor is not responding. Reseat its
      cable, then run the check again."
- [ ] **Silent servo**: a failed `wake-motors` with a joint shows "Left knee did not
      answer the check. Reseat its cable, then run the check again."
- [ ] **Arms unchanged**: the DK1 and SO-101 flows render exactly what they render today.
- [ ] **Retry stays**: the existing retry affordance on a failed check is untouched; the
      sentence tells the operator what to do before pressing it.

### Technical Requirements

- [ ] **Component test**: `VerifyStep.test.tsx` (or the nearest existing test) covers:
      duck + `IMU_NOT_FOUND` → IMU sentence; duck + `MOTORS_SILENT` +
      `lastErrorJoint = 'left_knee'` → labelled sentence; arm + `MOTORS_SILENT` → arm
      sentence; duck + unknown code → `checkFailedPlain`.
- [ ] **Placeholder guard**: no `{joint}` or backtick reaches the DOM
      (`duckErrorCopy.test.ts` covers the strings; the component test covers the render).
- [ ] **Store**: `runCheck` sets `lastErrorJoint` alongside `lastErrorCode` (2.1 makes
      this available; verify it is set on this path).

  manifest's `joints[].label`.

### Core Functions to Implement

```ts
// app/src/lib/checkFailureCopy.ts
export type CopyVariant = 'arm' | 'duck'

export function checkFailureText(
  code: string | null,
  joint: string | null,
  variant: CopyVariant,
  robot: RobotManifest | undefined,
): string | undefined {
  if (!code) return undefined
  const jointLabel = joint ? robot?.joints.find((j) => j.name === joint)?.label ?? joint : undefined
  if (variant === 'duck') {
    const text =
      strings.connect.duckErrors[code] ?? strings.duckErrors[code] ?? strings.errors[code]
    return text ? plainCopy(text, { jointLabel }) : undefined
  }
  return strings.errors[code]
}
```

### Technical Considerations

#### Why the connect vantage comes first

- The check runs on the connect screen, where "run the check again" is the action in
  front of the operator. `connect.duckErrors` is written for that screen;
  `duckErrors` is the Drive-page fallback if a code lacks a connect sentence.

#### Error Scenarios to Handle

- Code with no duck entry at all: falls to `strings.errors` and then to
  `checkFailedPlain`, as today.
- Joint present for a code whose sentence has no `{joint}`: `plainCopy` ignores unused
  vars.

#### Performance & UX

- None; string lookup at render time.
