# User Story 2.1: Carry the agent's code and joint to the frontend

## Story

**As a** Studio frontend
**I want** the agent's refusal code and the silent joint's name to arrive as fields, not prose
**So that** one sentence can name the part without parsing a log line

## Background

Repo: **tnkr-studio** (`server/trlc_studio` and `app/src`). This story is the backend and
transport half of the Studio side; 2.2 is the copy and the toast.

`agent_client._request` (`server/trlc_studio/robots/openduck_mini/agent_client.py:196-260`)
already reads the agent's dict detail and picks `ErrorCode` by name. Two gaps:

1. `IMU_NOT_FOUND` is not an `ErrorCode` member, so an agent that sends it falls through to
   the status map, and an unmapped 502 becomes `AGENT_FAILED`, whose sentence points at the
   agent, not a cable.
2. The agent's `joint` is folded into `detail` as `[left_knee] ...` and `detail` is
   log-only by design (`errors.py:252`). A pre-flight refusal has no screen state to name
   the joint from, so the joint has to travel as its own field, Pi → Studio backend →
   frontend.

Every new `ErrorCode` needs a `_STATUS` entry (unlisted codes silently fall back to 400,
`server/tests/test_error_codes.py:57`) and a sentence in `strings.ts`, or
`server/tests/test_error_copy.py::test_every_operator_facing_code_has_copy` fails. So this
story lands the `IMU_NOT_FOUND` entries in `strings.duckErrors` and
`strings.connect.duckErrors` too, with the agreed sentences; 2.2 refines the rendering.

**Ship order matters**: Studio first. A runtime deployed ahead of this story degrades to
`AGENT_FAILED` on a refusal; a Studio deployed ahead of the runtime changes nothing.

## Acceptance Criteria

### Core Functionality

- [ ] **New code**: `ErrorCode.IMU_NOT_FOUND = "IMU_NOT_FOUND"` in
      `server/trlc_studio/errors.py`, with a comment in the style of `MOTORS_SILENT` (why
      it is distinct from `SERVO_BUS_UNAVAILABLE`), and `_STATUS[IMU_NOT_FOUND] = 502`.
- [ ] **Joint on the error**: `StudioError.__init__(code, detail="", joint=None)` stores
      `self.joint`; `_studio_error` in `app.py:303` adds `"joint": exc.joint` to the JSON
      body only when set.
- [ ] **Joint from the agent**: `_request`'s dict-detail branch passes
      `joint=raw.get("joint")` (string or `None`) into `StudioError`. `detail` keeps its
      current `[joint] message` form for the log.
- [ ] **Frontend error type**: `StudioApiError` (`app/src/lib/api.ts:71`) gains
      `readonly joint: string | null`; `httpApi.ts` reads `body.joint` when building it.
- [ ] **Store**: `lastErrorJoint: string | null` next to `lastErrorCode`
      (`app/src/lib/store.ts:131`), set wherever `lastErrorCode` is set from a
      `StudioApiError`, cleared where it is cleared.

### User Experience

- [ ] **Sentences exist**: `strings.duckErrors.IMU_NOT_FOUND` = "The IMU sensor is not
      responding. Reseat its cable, then press Walk again." and
      `strings.connect.duckErrors.IMU_NOT_FOUND` = "The IMU sensor is not responding.
      Reseat its cable, then run the check again."
- [ ] **No change on other robots**: arm screens never see these codes.

### Technical Requirements

- [ ] **Mapping tests**: `server/tests/test_openduck_agent.py` gains, via `_raise_from`:
      502 + `{"code": "IMU_NOT_FOUND", "message": "..."}` → `err.code == IMU_NOT_FOUND`;
      502 + `{"code": "MOTORS_SILENT", "joint": "left_knee", ...}` →
      `err.joint == "left_knee"`; dict without `joint` → `err.joint is None`.
- [ ] **Status test**: `test_error_codes.py` asserts `IMU_NOT_FOUND` → 502.
- [ ] **Serialisation test**: a `StudioError` with a joint renders `{code, detail, joint}`;
      without one, `joint` is absent.
- [ ] **Copy test**: `test_error_copy.py` passes with no `NOT_SHOWN` addition.
- [ ] **API types**: `SessionSnapshot` is unchanged, so `npm run check:api-drift` stays
      clean. The error body is not in the OpenAPI schema today; keep it that way.

## Expected User Flow

```bash
# Studio backend, agent refused the walk
$ curl -s -X POST localhost:8000/walk/start -H 'content-type: application/json' -d '{"input":"keyboard"}'
HTTP/1.1 502
{"code":"MOTORS_SILENT","detail":"[left_hip_yaw] 1 of 14 servos did not answer: left_hip_yaw","joint":"left_hip_yaw"}

$ curl -s -X POST localhost:8000/walk/start -d '{}'
HTTP/1.1 502
{"code":"IMU_NOT_FOUND","detail":"ValueError: No I2C device at address: 0x28"}
```

```ts
// frontend, after startWalk() resolves false
useStudio.getState().lastErrorCode   // 'MOTORS_SILENT'
useStudio.getState().lastErrorJoint  // 'left_hip_yaw'
```

### Technical Considerations

#### Backwards compatibility

- **Older agent**: never sends `joint` or `IMU_NOT_FOUND`; nothing changes.
- **Older frontend bundle against a new backend**: ignores the extra `joint` key.
- **`detail` unchanged**: existing tests asserting `"left_knee" in err.detail` keep passing.

#### Error Scenarios to Handle

- `joint` present but not a string: treated as absent.
- Unknown code name from a future agent: existing fallback to the status map, unchanged.

#### Performance & UX

- None; a field on an error.
